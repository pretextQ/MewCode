### 1. 受保护路径禁写

参考：`D:\Downloads\mewcode-python\mewcode\permissions\sandbox.py:15` 默认保护 `.mewcode/config.yaml`、`.mewcode/permissions.local.yaml`、`.mewcode/skills/`；`permissions/checker.py:115` 在写工具权限模式兜底前调用保护检查。

当前：`mewcode/permissions/sandbox.py` 只有允许路径范围，缺少这层专门保护。离线探针中，bypass 下三个目标的 WriteFile 判定均为 allow；参考库均为 deny，普通源码文件均为 allow。这里只检查权限判定，没有向这些文件写入内容。

建议：保留当前规则拒绝优先、路径解析与沙箱约束，额外引入受保护目标检查。写权限规则和安装技能的专用操作要走明确接口，不能顺手禁用现有“始终允许”的规则持久化。是否涵盖全局配置和项目级 `permissions.yaml` 应一并定义。该层约束内置文件工具，不能声称它能阻止任意 Shell 写入；需要与真实执行边界区分。

不要整份照搬参考权限检查器：它还存在提前放行路径，当前实现已有不同且更严格的判定顺序。

### 2. 指令文件加载

参考：`memory/instructions.py:136` 从 Git 根目录向工作目录逐级加载；`:159` 支持全局与项目 `MEWCODE.md`、`AGENTS.md` 和 `MEWCODE.local.md`。include 还做了循环检测和代码围栏跳过。

当前：`mewcode/memory/instructions.py:50` 仅加载工作目录 MEWCODE.md、其 `.mewcode/MEWCODE.md` 及全局 MEWCODE.md；不读取 AGENTS.md 和父级指令链。临时项目探针已验证这个差异。

建议：先补 AGENTS.md、根到工作目录的确定顺序、来源标签和本地覆盖文件；保持当前 `@include` 兼容。include 可吸收循环检测、代码块排除，但保留当前项目外路径限制，避免参考实现允许任意绝对路径/用户目录包含带来的边界变化。启动时按工作目录加载并不等于自动识别此后任意被编辑文件的目录规则，两者应分开设计。

### 3. 崩溃诊断

参考：`crashlog.py:21` 追加带时间戳日志，`:34` 保存异常堆栈，`:42` 安装 faulthandler、进程启动和正常退出标记，主入口和 Textual 异常入口有接线。

当前：`mewcode/__main__.py:190` 已有 debug.log，但 `filemode="w"` 会在启动时覆盖；未发现对应 crashlog/faulthandler 接线。

建议：沿用当前 `MEWCODE_LOG_FILE` 的容器日志定位能力，加进程/会话标识、异常堆栈和追加/轮转策略；日志不记录凭据或完整敏感请求。start/exit 标记只能提供退出线索，不能独自证明崩溃原因。本项是静态确认，未实际触发进程崩溃。

### 4. 拒绝授权时附带反馈

参考：`permission_dialog.py:102` 产生 `PermissionReply(response, feedback)`，`agent.py:1016` 把用户反馈写入拒绝工具结果；`tests/test_permission_feedback.py` 覆盖输入、粘贴、取消及反馈进入后续对话。

当前：`mewcode/permission_dialog.py:84` 只返回 PermissionResponse；Agent 收到 DENY 后没有对应反馈字段。

建议：例如拒绝写入时输入“改存到 backup 目录”，Agent 在下一轮收到明确纠正。需要同时适配交互入口、请求 future、取消收尾和工具拒绝文案；沿用 A5 的真实拒绝/中断区别。优先吸收这一交互能力，不替换当前黑色 TUI 布局。本项已阅读源码及测试，未运行交互验收。

### 5. 编辑后显示 diff

参考：`tools/edit_file.py` 成功返回增删摘要与 diff；`tools/diff.py:22` 提供带行号、上下文和最多 200 行的展示。

当前：`mewcode/tools/edit_file.py` 成功主要返回文件名，`mewcode/tui/tools.py` 可以显示输出，但没有这种编辑差异。现有 Git 详情不能等同于每次工具编辑的前后对照。

建议：在当前正确的编辑逻辑完成后，用前后内容生成有界预览，保留现有编码、CRLF、读取状态校验、撤销历史和缓存失效。参考算法只裁公共前后缀，多处相距很远的修改会把中间未变内容也算作删除/添加；可借展示方式，不能直接将其计数当准确 diff 统计。

### 6. MCP 加载策略

参考：`mcp/loading_strategy.py:65` 依 schema 规模与端点选 eager/native/dispatch；`tools/mcp_call.py:143` 提供统一分发入口，ToolSearch 返回 schema 或工具引用。其重要思路是：小集合直接暴露，大集合检索后调用，尽量避免发现工具时改变 tools 数组。

当前：`mewcode/tools/impl/tool_search.py:50` 将命中的工具 mark_discovered，后续 tools 集合发生变化。离线探针对一个假 MCP 工具确认 schema 数量从 0 变为 1；这证明集合变化，不证明实际缓存损失或费用变化。

建议：先量化实际接入工具数量、schema 大小和请求行为，再选择收益是否足够。若需要实施，先支持 eager 与兼容端点的分发路径；同时保留工具启停、协调模式过滤、MCP 只读约束及真正目标工具的权限检查。统一入口不能绕过这些检查，也不能照搬参考实现对任意注册工具名的宽泛解析。工具命名当前为 `mcp_server_tool`，参考为 `mcp__server__tool`，要兼容现有配置。

验证限制：参考 MCP runtime 在当前项目虚拟环境下导入失败（`mcp.Client` 不存在），因此没有伪装为完整链路验证。仅直接加载无运行时 MCP 依赖的策略模块，验证小集合→eager、大集合兼容地址→dispatch、大集合默认地址→native 的分支选择。native 的真实端点支持、工具引用与实际缓存表现均未验证；不沿用参考注释里的缓存命中率数字。

### 7. Shell 的语义和并发

参考：`tools/bash.py:129` 按具体命令判断并发安全；当前 Bash 继承固定的 `is_concurrency_safe=False`，所有 Shell 调用串行。可吸收严格白名单下的只读命令并发，但当前 Agent 消费的是布尔属性，不能直接把它换成同名方法，否则方法对象的真值会误导分批逻辑。

退出码更适合先补明确的数字/语义：当前非零返回 is_error=True，输出可能只有 `(no output)`，对模型诊断不够充分；可以明确区分搜索无匹配、diff 有差异、真正执行失败。

不要直接移植参考执行方法：探针运行无副作用的 `cmd /c exit 7`，当前判错，参考输出 `Exit code 7` 却 `is_error=False`。参考 `_interpret_exit_code` 虽有分类逻辑，execute 的实际返回没有使用它。保留当前进程树回收、取消、超时和输出大小限制。

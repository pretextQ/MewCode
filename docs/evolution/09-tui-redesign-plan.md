## 1. 已确认方向与交付范围

用户认为现有界面角色和状态难以区分，并认可按本次讨论规划后续 TUI 改造。保留 Python/Textual TUI 与现有共享 Agent 内核。**用户消息不单独显示“你 / User / U”标题**，正文用小 `›` 前缀、低饱和底色、左侧边线与留白区分；不因去掉标题而丢掉内部消息角色。助手用轻量 `✦ MewCode` 起始标记，工具有独立摘要；不照搬其他产品的品牌、代码或未经确认的功能。

建议最终组合是“专注对话为默认 + 可收起的开发详情侧栏”；两者是同一 TUI 的布局模式，避免维护两套执行与消息逻辑。先完成基础交互，再接真实数据的侧栏。侧栏建议阈值为至少 120 列、24 行，实际以字符宽度测试校准；窄终端默认收起，详情改用可关闭视图，不挤走输入区。

此前交互预览只用于设计讨论：其中 U 标签已被本计划的最终决定取代；时间、diff、测试结果和权限场景均为示例，不代表实现或验收。克隆仓库不依赖聊天中的本地预览文件即可按本计划实施。

本期不迁移桌面/Web UI，不改 Agent 策略、权限决策、服务调度、存储格式或监督语义，不新增执行权限、模型调用、请求额度或自动重试。不同时推进 token 预警、GitHub 评审接入、多 Agent 迁移等其他路线。

## 3. 界面规格

### 布局与视觉

- 用户实际截图反馈后明确以浅色对话/工作台参考图对齐：顶部保留独立产品标记/版本栏，下一栏显示项目、分支及右侧**配置中的模型标识**，不能全部压成单行；默认采用浅色背景、紫色强调和输入卡片。长路径折叠，完整信息按需查看。分支未知时如实显示，不阻塞首屏；禁止依赖模型自述决定模型名称。模型回复内容本身仍是模型输出，不用字符串替换伪装已解决身份问题。
- 中部对话区独立滚动。用户、助手、工具、错误分别有稳定的文字/符号/边界；普通正文保持足够对比度，辅助信息弱化但可读，不仅靠颜色区分。
- 底部独立运行状态行、固定输入区域及快捷键提示。输入框有明确焦点边界和多行高度上限；聊天内容再长也不能把它推出可见区。大幅缩小时优先压缩装饰和元信息，不坚持 chat-area 的固定最小高度。
- 流式回复、结束后的 Markdown、恢复的历史消息样式一致，避免流式结束后跳位、重复内容或吞掉片段。工具详情折叠不影响正文选择和滚动位置。
- 首期使用统一的语义颜色和间距 token，兼顾 Windows Terminal、常见 Linux 终端及中英文/全角字符。减少三行大 banner 和随机英文 thinking 动词对历史的占用；不扩展为主题编辑器。

### 状态与操作

只投影已有事实，不另造第二套 Agent 执行状态机。建议有 `待输入 / 连接工具 / 等待模型响应 / 执行工具 / 等待权限 / 等待用户回答 / 取消中 / 已停止 / 出错 / 本次运行结束`。有显式阶段事件才显示“正在验证”；普通 Bash 成功不能变成“测试通过”。

| 场景 | 可见反馈与行为 |
| --- | --- |
| 等待模型或工具 | 单独状态行显示动作与已耗时，提供 Esc 停止提示；不在正文不断追加 spinner 文案 |
| MCP 连接 | 区分连接中、成功、部分失败；不把应用启动等同于所有 MCP 可用 |
| 权限确认 | 显示真实工具、命令/路径、现有允许范围及拒绝动作；等待期间不得执行。保持现有默认选择和审批范围，不增“始终允许”快捷授权 |
| 用户问题/计划审批 | 焦点进入对应控件，答案与计划动作保持原语义；退出后返回合理焦点 |
| 取消 | 按当前焦点优先处理弹窗、补全菜单，再取消执行；先显示取消中，任务收尾确认后再显示已停止，不宣称回滚已有修改 |
| 正常返回 | 显示本次运行结束，完成声明保留为助手回复；没有真实验证证据时不显示“任务成功/验证通过” |
| 流错误/工具失败 | 保留已有回复、错误和改动线索；不清空输入草稿、不自动重跑命令 |

首期保留 Enter 发送、Shift+Enter / Ctrl+J 换行、Tab 补全、上下键历史、Shift+Tab 模式切换、Ctrl+O 工具展开、Esc 和 Ctrl+C 的既有语义。新增 F2 切换详情是本期建议，实施前核对冲突并在帮助中登记。等待回复期间维持现有发送约束并清楚提示，不悄悄引入消息排队或中途 steer 新语义。滚动离开底部后保留阅读位置，提供返回最新位置的可见入口；自动跟随仅在用户处于底部时启用。

### 真实数据的开发详情

- 任务区域仅显示已有任务/计划数据；无结构化计划就显示当前请求摘要或空态，不从模型散文编造完成勾选、百分比或 ETA。
- 工具摘要展示真实名称、目标、执行/失败/取消状态和耗时；单项可通过键盘与鼠标展开。保留输出量限制与截断标记，不默认渲染无限日志；自定义/MCP 工具没有已知语义时照实显示。
- 侧栏最小包含“工作区改动”和“执行记录”两页。前者保守使用只读 Git diff，并明确**可能包含原有未提交改动**，不能冒称均为本任务生成。非 Git 仓库给出空态。未跟踪文件首期只列路径、不自动读取任意内容；不自动展示凭据或忽略文件。
- Git 查询按需、异步、有超时与输出上限，不按每个模型 token 刷新；禁用外部 diff/textconv 等可执行扩展。复用已有安全读取路径，结果和命令输出按纯文本展示，禁止把任意文件文本当 Rich 标记执行。
- 验证结果仅展示现有显式证据和输出；能确认的退出码、工具成功、验证尝试和覆盖范围各自标注。沿用 self-verify 的 coverage=unknown；Agent 正常结束、模型说“通过”和监督 adopted 都不能升级为验证通过。没有可靠解析时显示“命令已结束/输出待查看”，不臆造 passed 数字。
- 模型/权限/MCP 状态来自配置和运行时。token 只显示已知来源与口径；未知值用 `—/未知`，不虚构实时容器用量、剩余额度、价格或进度。

## B：第三阶段最小监督内核

参考[监督设计](06-tianshu-supervision-notes.md)，以纯 Python 独立实现，不移植上游复杂框架。A 交付后继续完成本项，不把所有行为检测器混入首期。

### B1 数据与生命周期

- 定义真实模型轮次、run ID、任务/attempt 边界、提醒去重键、优先级/分类、通道、TTL、可选 expect 和核销结果；不以工具调用次数代替模型轮数。
- 明确新 run、用户 steer、重试与恢复的重置/保留语义，子代理之间隔离；不让旧提醒无界累积或持久化重放。
- 最小提醒总线支持去重、显式通道数量/字节预算、优先级与过期；不照抄上游阈值，写清本项目选择与理由。

### B2 实际接线与核销

- 接入交互 run、headless run_to_completion；服务直跑和容器内 Agent 必须遵循相同内核语义，配置能端到端传入，不能只写未接线模块。
- 提醒被选中、出队或渲染不等于送达；只在本次真实请求携带该提醒的明确时点确认送达，定义请求失败/取消/重试行为。
- 有 expect 区分等待、采纳和窗口到期未采纳；无 expect 仅计送达。被裁掉、尚未注入、失败未送达的提醒不得计 ignored；尝试验证不等于验证通过。
- 保留现有 hooks 的用户扩展语义，不把监督基础与用户 hooks 混为一体。默认关闭；关闭时不增加模型请求、提示内容和外部动作。
- 提供最小结构化事件/报告以核对总线真实工作；不能为证明运行而默认开启 detector 或注入额外测试要求。

### B 验收与交付

构造实际循环测试证明：多通道预算、去重、TTL、送达、expect 核销、关闭兼容、run 重置、steer、失败/取消/重试、子代理隔离与配置传递。真机容器验证适用时补跑；不以纯总线单测冒充跨模式完成。记录首期边界，说明没有 detector 的基础设施不等于监督效果已改善。

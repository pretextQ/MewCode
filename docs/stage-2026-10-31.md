## 交付范围

本次交付第三阶段的第一个内置 detector：执行循环预算预警。沿用现有监督开关，默认关闭，不新增依赖或配置字段。交互 `run` 与 headless `run_to_completion` 每次允许进入循环后检查剩余硬额度；服务直跑、容器及子代理复用 Agent 实现。

预警在最后 `ceil(max_iterations / 10)` 次循环触发，至少一次，包含当前循环；默认 50 次时第 46 次开始。每 run 最多发布一次，受现有 TTL、去重、容量及通道字节预算约束。发布不代表送达，首个响应确认后才记 delivered；没有 expect，不会冒称采纳或验证通过。新 run 重新武装，steer 不重新发布同一 key。延迟投递的文案不携带可能已过时的精确剩余量，结构化事件保留发布时额度。

明确区分执行循环硬上限和真实模型响应 turn：请求重试及上下文恢复可能导致二者不同。这个 detector 不是 token 预警，不改变 token 熔断、权限、请求次数或最大循环数，也不追加收尾轮。预警建议优先进行适用验证、说明失败与未验证部分，不为只读任务强加无关测试。

实现位置：`mewcode/supervision/detectors.py`；两条循环各增加一个调用。新增 `tests/test_supervision_detectors.py` 20 项，真实容器 probe 增加新 run 的内置预警送达断言。使用假 LLM 验证接线，没有调用付费模型或创建远端修复 PR。

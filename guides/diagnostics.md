# 进程诊断

CLI、headless、service 和独立 worker 的启动入口会初始化诊断；TUI 同时接入 Textual
异常出口及发送消息异常，异步和线程异常仍交给原处理器。记录启动/退出标记、PID、
随机进程会话标识、异常类型与最多 30 帧堆栈；不改变原退出码或吞掉异常。
同一异常对象不重复记录，重复初始化也不会添加第二组处理器。

`MEWCODE_LOG_FILE` 继续指定普通日志位置，默认 `.mewcode/debug.log`。普通日志追加，
约 2 MiB 轮转，保留 3 个备份。异常文本清理常见 api_key/token/password、Bearer、
`sk-` 密钥和 URL 用户凭据，单条日志截断到约 32000 字符。不主动记录配置、模型请求、
完整响应或会话正文；清理是常见格式处理，不保证任意自定义秘密都能被识别。

诊断保存在同级 `<日志文件名>.diagnostics/<PID>-<会话标识>/`：

- `events.log`：追加并按同样大小轮转的结构化事件文本。
- `fault.log`：faulthandler 的稳定文件描述符，普通日志轮转不影响它。
- `.lease`：进程持有的跨平台锁，保留清理跳过仍在运行的进程。

启动时保留最近 20 组，清理超过保留数且无活跃锁的旧组；活跃组可以使总数暂时超过 20。
faulthandler 文件在进程存活期间不轮转，退出清理时仅保留末尾约 1 MiB 并标记截断。
硬终止可能跳过清理，留下原始 fault 文件；下次保留清理会处理旧组。
普通日志的单条记录有界，UTF-8 与单条写入可能使轮转文件略超过阈值。
重定向日志后所有这些文件都跟随日志目录，不写入修复 worktree。

无法创建目录、写入失败等只降低日志可用性，不造成应用二次崩溃。faulthandler 仅提供
底层堆栈线索，不包含 Python 局部变量；它不能捕获所有硬退出或断电。缺少退出标记
只能说明没有记录退出，不能单凭此确定崩溃原因。`atexit (exit code unknown)` 表示
清理运行了但没有经过 CLI 的明确退出路径，不等于成功。日志异常、真实平台和模型效果
应分别评估；本项未使用真实模型预算。

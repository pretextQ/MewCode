# 团队代码规范自查清单（org code style）

修复完成后**逐项**核对，并在最终报告里输出 `SELF-CHECK:` 段落，每项一行
`- [x] 结论` 或 `- [ ] 未满足：原因`。核对的是你这次改动引入的部分。

> 这是可替换的起步模板：团队应改写成自己的真实标准（命名约定、日志格式、
> 错误码规范、review 关注点）。改这个文件即可生效，不需要改代码。

1. **错误处理**：新增/修改的代码对失败路径有明确处理，不吞异常，不写裸 `except: pass`。
2. **日志**：日志点使用项目既有 logger/格式，包含定位所需上下文（关键 id、参数），不打印密钥。
3. **测试**：改动有对应验证（复用既有测试或新增用例），且验证命令实际跑过。
4. **最小 diff**：没有顺手重构、格式化无关代码或引入不必要依赖。
5. **命名与风格**：命名清晰一致，与文件内既有风格统一（不用另一种惯用法）。
6. **边界条件**：空值/空集合/零值/超时/重试等边界显式考虑过。
7. **安全**：不硬编码密钥或凭证，不把用户输入拼进命令/SQL。
8. **可回滚**：改动不破坏既有公开行为；若有意改变行为，已在报告中说明。
